# 天枢智航架构

系统采用模块化单体。HTTP/WS 属于适配层，仿真和算法不依赖 FastAPI。

| 模块 | 职责 |
| --- | --- |
| backend/api、models | 请求校验、HTTP 与 WebSocket 协议 |
| backend/services | 应用编排、事务、实体关联校验 |
| core/models、coords | 领域数据、米制局部坐标及显示坐标转换 |
| core/repository | 仓储协议、SQLite 持久化、内存测试后端 |
| algorithms | 可解释、可单测的规划和协同算法 |
| simulation | 仿真时钟、状态推进、环境、动态事件和实际指标 |
| frontend | Vue 3 控制台、Three.js 三维城市场景和 ECharts 图表 |

依赖方向：backend → simulation → algorithms → core；backend 也可直接依赖 core。
算法接收明确的数据快照，不从 Web 请求或全局配置中取状态。

## 数据一致性

一个应用实例持有一个 Registry，使用共享可重入锁协调实体事务和环境快照安装。
SQLite 是默认存储；内存后端用于隔离测试。仓储返回副本，修改必须显式写入。
实体和元数据在同一事务中提交。Demo 场景先校验和构建，再替换当前状态。
城市建筑保存实际生成结果，重启恢复不会因随机数或航点变化重新生成城市。

MVP 部署使用单个 Uvicorn worker。实时仿真由唯一执行循环推进，运行期间的
控制动作经过该实例同步处理。扩展到多个服务实例前，必须引入明确的场景所有者。

## 算法边界

建筑、关闭空域和飞行能力属于硬约束；距离、风险、拥堵、能耗、可接受天气扰动
参与非负加权代价。每次规划返回分项代价和选择原因。
高级算法只能以相同输入输出契约替换传统策略；没有训练、验证的模型不标记为 AI 能力。

## 时间与指标

UTC 时间用于审计，仿真秒用于飞行、轨迹、事件调度和延误。算法执行耗时以真实单调时钟测量。
图表数据来自仿真状态及记录；场景配置可以固定随机种子，不能预填展示结果。
